## Lab 2: Simulate Suspicious Activity, Capture Evidence, and Rank Risk

This lab bridges system administration skills into SOC-style investigation workflows. You will generate controlled suspicious activity on your Amazon Linux 2023 EC2 instance, collect evidence with journalctl and basic audit checks, then run a Python script that scores and ranks suspicious events.

### Safety Rails

- Run this lab only in your training environment.
- Do not run destructive tools, malware, or exploit frameworks.
- Keep all activity controlled and documented.
- AI is not used in this lab yet. This is the evidence and scoring foundation for later AI-assisted labs.

## Learning Objectives

By the end of this lab, you will be able to:

1. Generate realistic, non-destructive suspicious activity for detection testing.
2. Collect and pivot Linux authentication and privilege events.
3. Review sudo policy exposure in sudoers configuration.
4. Parse log evidence with Python and assign explainable risk scores.
5. Produce ranked, analyst-ready findings with evidence references.

## Part 2: Generate Controlled Suspicious Events

### A) Failed SSH Attempts (Primary Signal)

From CloudShell or another terminal, run a few failed SSH attempts against your instance public IP:

```bash
ssh fakeuser@YOUR_PUBLIC_IP
```

Enter an incorrect password a few times when prompted, then exit. Repeat 3-5 times.

Expected signal:
- Failed auth events in sshd logs.
- Source IP visible in the log message.

### B) Optional Recon Scan and Detection (Secondary Signal)

If nmap is available from your scanning host:

```bash
nmap -Pn -sS -p 1-1024 YOUR_PUBLIC_IP
```

Expected signal:
- Some environments show SSH probe patterns in sshd logs.
- Closed ports may not always be logged by default on Amazon Linux 2023, so SSH-side probe traces are the primary scan indicator in this lab.

Detection pivots:

```bash
# Look for probe-like SSH behavior that often appears during scanning/recon.
sudo journalctl -u sshd --since "30 min ago" --no-pager | grep -Ei "did not receive identification|string|connection closed|unable to negotiate"

# Count repeated probe-related events by source IP.
sudo journalctl -u sshd --since "30 min ago" --no-pager \
    | grep -Ei "did not receive identification|string|connection closed|unable to negotiate" \
    | grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' \
    | sort | uniq -c | sort -nr
```

### C) Local sudo Activity (Privilege Signal)

On the EC2 instance, run:

```bash
sudo -k
sudo -l
sudo ls /root
```

Expected signal:
- sudo command activity in journal logs.
- Useful for privilege-related detection logic.

## Part 3: Collect Evidence with journald and Audit Tools

1. Export SSH and sudo journal data as JSON lines for parsing.

```bash
cd ~/soc-lab2
sudo journalctl -u sshd --since "30 min ago" -o json > sshd.jsonl
sudo journalctl _COMM=sudo --since "30 min ago" -o json > sudo.jsonl
```

2. Quick checks that files contain events.

```bash
wc -l sshd.jsonl sudo.jsonl
head -n 2 sshd.jsonl
head -n 2 sudo.jsonl
```

3. Optional audit status check.

```bash
command -v auditctl || echo "auditctl not installed"
sudo systemctl status auditd --no-pager || true
```

If `auditctl` is not installed (common on some Amazon Linux 2023 images), install and enable it:

```bash
sudo dnf install -y audit
sudo systemctl enable --now auditd
sudo auditctl -s
```

4. Optional sudoers review and permission hygiene check.

```bash
sudo ls -l /etc/sudoers /etc/sudoers.d
sudo grep -R "NOPASSWD" /etc/sudoers /etc/sudoers.d 2>/dev/null
```

Note:
- NOPASSWD is not always bad, but broad NOPASSWD entries increase risk and should be reviewed.

## Part 5: Python Risk Scoring Script

Create `risk_ranker.py` with the code below.

```python
import json
import re
from collections import defaultdict
from datetime import datetime

SSH_FILE = "sshd.jsonl"
SUDO_FILE = "sudo.jsonl"

# Explainable starter weights.
WEIGHTS = {
    "ssh_failed_password": 3,
    "ssh_invalid_user": 4,
    "ssh_ident_probe": 2,
    "ssh_scan_pattern": 4,
    "ssh_burst_scan": 8,
    "sudo_activity": 2,
    "sudo_root_access": 5,
}

IP_REGEX = re.compile(r"from\s+((?:\d{1,3}\.){3}\d{1,3})")


def load_jsonl(path):
    events = []
    with open(path, "r", encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            try:
                events.append(json.loads(line))
            except json.JSONDecodeError:
                continue
    return events


def parse_ts(event):
    # journald uses microseconds since epoch in __REALTIME_TIMESTAMP
    raw = event.get("__REALTIME_TIMESTAMP")
    if not raw:
        return None
    try:
        micros = int(raw)
        return datetime.utcfromtimestamp(micros / 1_000_000)
    except (ValueError, OSError):
        return None


def classify_ssh(message):
    m = message.lower()
    if "failed password" in m:
        return "ssh_failed_password"
    if "invalid user" in m:
        return "ssh_invalid_user"
    if "did not receive identification" in m:
        return "ssh_ident_probe"
    if "connection closed" in m or "unable to negotiate" in m:
        return "ssh_scan_pattern"
    return None


def classify_sudo(message):
    m = message.lower()
    if "sudo" not in m:
        return None
    if "command=" in m and ("/root" in m or "command=/bin/" in m):
        return "sudo_root_access"
    return "sudo_activity"


def severity_from_score(score):
    if score >= 20:
        return "high"
    if score >= 10:
        return "medium"
    return "low"


def main():
    ssh_events = load_jsonl(SSH_FILE)
    sudo_events = load_jsonl(SUDO_FILE)

    findings = defaultdict(lambda: {"score": 0, "hits": defaultdict(int), "evidence": []})

    # Track timestamps for burst-style scan detection by source IP.
    ssh_ip_times = defaultdict(list)

    for e in ssh_events:
        msg = e.get("MESSAGE", "")
        kind = classify_ssh(msg)
        if not kind:
            continue

        ip_match = IP_REGEX.search(msg)
        entity = ip_match.group(1) if ip_match else "unknown-ip"
        weight = WEIGHTS[kind]

        findings[entity]["score"] += weight
        findings[entity]["hits"][kind] += 1
        ts = parse_ts(e)
        if ts is not None:
            ssh_ip_times[entity].append(ts)
        if len(findings[entity]["evidence"]) < 3:
            findings[entity]["evidence"].append({
                "ts_utc": str(ts),
                "message": msg,
            })

    # If many SSH events from one IP occur in <=60 seconds, treat as likely scan burst.
    for entity, times in ssh_ip_times.items():
        if len(times) < 8:
            continue
        times_sorted = sorted(times)
        window_start = 0
        max_in_window = 0
        for window_end in range(len(times_sorted)):
            while (times_sorted[window_end] - times_sorted[window_start]).total_seconds() > 60:
                window_start += 1
            current = window_end - window_start + 1
            if current > max_in_window:
                max_in_window = current

        if max_in_window >= 8:
            findings[entity]["score"] += WEIGHTS["ssh_burst_scan"]
            findings[entity]["hits"]["ssh_burst_scan"] += 1
            if len(findings[entity]["evidence"]) < 3:
                findings[entity]["evidence"].append({
                    "ts_utc": str(times_sorted[0]),
                    "message": f"Burst SSH activity detected: {max_in_window} events within 60 seconds",
                })

    # Track sudo as a host-level signal.
    host_entity = "host-local"
    for e in sudo_events:
        msg = e.get("MESSAGE", "")
        kind = classify_sudo(msg)
        if not kind:
            continue

        weight = WEIGHTS[kind]
        findings[host_entity]["score"] += weight
        findings[host_entity]["hits"][kind] += 1
        if len(findings[host_entity]["evidence"]) < 3:
            findings[host_entity]["evidence"].append({
                "ts_utc": str(parse_ts(e)),
                "message": msg,
            })

    ranked = sorted(findings.items(), key=lambda x: x[1]["score"], reverse=True)

    print("entity,severity,score,hit_summary")
    for entity, data in ranked:
        hit_summary = "|".join(f"{k}:{v}" for k, v in sorted(data["hits"].items()))
        sev = severity_from_score(data["score"])
        print(f"{entity},{sev},{data['score']},{hit_summary}")

    print("\nTop evidence snippets:")
    for entity, data in ranked[:5]:
        print(f"\n[{entity}] score={data['score']} severity={severity_from_score(data['score'])}")
        for ev in data["evidence"]:
            print(f"- {ev['ts_utc']} | {ev['message']}")


if __name__ == "__main__":
    main()
```

Run it:

```bash
python3 risk_ranker.py
```

## Risk Score Reference

| Signal | Weight | Why It Matters |
| --- | --- | --- |
| `ssh_failed_password` | 3 | Repeated failures can indicate brute-force behavior |
| `ssh_invalid_user` | 4 | Login attempts against unknown accounts are high-suspicion |
| `ssh_ident_probe` | 2 | Banner/probe behavior can be recon activity |
| `ssh_scan_pattern` | 4 | SSH probe signatures suggest active reconnaissance |
| `ssh_burst_scan` | 8 | High event rate from one IP in a short window is scan-like behavior |
| `sudo_activity` | 2 | Privilege use should be reviewed in context |
| `sudo_root_access` | 5 | Root-level command context has higher potential impact |
