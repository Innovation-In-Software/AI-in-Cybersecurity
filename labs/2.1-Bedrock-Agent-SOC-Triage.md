## Lab 4.0: Build and Test an Amazon Bedrock SOC Triage Agent

This lab is the first AI-enabled workflow in the course. You will create a specialized Amazon Bedrock Agent for SOC triage, build a Lambda function that invokes it, and manually test the workflow with Wazuh alert data from Lab 3.

The goal is not autonomous response. The agent assists with triage by summarizing evidence, extracting indicators, mapping likely ATT&CK-style behavior, and proposing next investigative steps while keeping a human analyst in control.

## Learning Objectives

By the end of this lab, you will be able to:

1. Create a Bedrock Agent specialized for security triage.
2. Build a Lambda function that invokes the agent safely.
3. Validate structured triage output against a required schema.
4. Preserve evidence and analyst review boundaries in an AI-assisted workflow.
5. Prepare the workflow for event-driven automation in the next lab.

---

## Architecture

Event flow for this lab:

1. Analyst provides a Wazuh alert file from Lab 3.
2. Lambda reads and sanitizes the alert data.
3. Lambda invokes the Bedrock Agent.
4. Lambda validates the JSON response.
5. Lambda returns structured triage output.
6. Analyst reviews the result before any action is taken.

## Part 1: Create the Bedrock Agent

Use the AWS console for this step so the lab stays within the 90-minute timebox.

1. Open Amazon Bedrock.
2. Go to Agents.
3. Create a new agent named `soc-triage-agent`.
4. Choose an enabled foundation model.
5. Use the instruction block below.
6. Create an agent alias after the agent is prepared.
7. Save the `AGENT_ID` and `AGENT_ALIAS_ID`.

Suggested agent instruction:

```text
You are a SOC triage assistant specialized in Linux endpoint and Wazuh-derived security events.

You must analyze only the provided event data and never invent facts.
You must return valid JSON and nothing else.
You do not approve containment, blocking, isolation, or deletion actions.
You only recommend analyst review steps.

Required JSON fields:
- severity: one of low, medium, high
- confidence: integer from 1 to 100
- summary: short analyst-ready summary
- iocs: list of strings
- likely_techniques: list of strings
- evidence: list of short evidence lines derived from the input
- recommended_next_steps: list of short analyst-safe next steps
- escalation_recommended: true or false
- uncertainty_notes: short explanation of unknowns or limits

Rules:
- Ground every finding in the supplied events.
- If evidence is weak, lower confidence.
- If data is incomplete, say so in uncertainty_notes.
- Never produce shell commands that perform containment or destruction.
```

Expected result:

- You have a callable Bedrock Agent and alias for the Lambda function.

## Part 2: Create the Lambda Function

Create a Lambda function named `soc-triage-bedrock-handler` with Python 3.12.

Environment variables:

- `AGENT_ID`
- `AGENT_ALIAS_ID`

IAM permissions needed for the Lambda role:

1. Write CloudWatch logs.
2. Invoke the Bedrock Agent.

Use this trust policy for the Lambda execution role:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Service": "lambda.amazonaws.com"
            },
            "Action": "sts:AssumeRole"
        }
    ]
}
```

Attach a permissions policy similar to this:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "logs:CreateLogGroup",
                "logs:CreateLogStream",
                "logs:PutLogEvents"
            ],
            "Resource": "*"
        },
        {
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeAgent"
            ],
            "Resource": "*"
        }
    ]
}
```

Use this handler code:

```python
import json
import os
import uuid

import boto3

agent_runtime = boto3.client("bedrock-agent-runtime")

AGENT_ID = os.environ["AGENT_ID"]
AGENT_ALIAS_ID = os.environ["AGENT_ALIAS_ID"]

REQUIRED_FIELDS = {
    "severity",
    "confidence",
    "summary",
    "iocs",
    "likely_techniques",
    "evidence",
    "recommended_next_steps",
    "escalation_recommended",
    "uncertainty_notes",
}


def sanitize_alerts(raw_text, max_events=10):
    sanitized = []
    for line in raw_text.splitlines():
        line = line.strip()
        if not line:
            continue
        try:
            ev = json.loads(line)
        except json.JSONDecodeError:
            continue

        rule = ev.get("rule", {})
        agent = ev.get("agent", {})
        data = {
            "timestamp": ev.get("timestamp"),
            "agent_name": agent.get("name"),
            "rule_level": rule.get("level"),
            "rule_description": rule.get("description"),
            "rule_groups": rule.get("groups", []),
            "full_log": ev.get("full_log", "")[:300],
        }
        sanitized.append(data)
        if len(sanitized) >= max_events:
            break
    return sanitized


def invoke_agent(alerts):
    prompt = {
        "task": "triage_security_alerts",
        "alerts": alerts,
        "instructions": "Return JSON only. Ground findings in the alerts."
    }

    response = agent_runtime.invoke_agent(
        agentId=AGENT_ID,
        agentAliasId=AGENT_ALIAS_ID,
        sessionId=str(uuid.uuid4()),
        inputText=json.dumps(prompt),
    )

    parts = []
    for event in response["completion"]:
        chunk = event.get("chunk")
        if chunk and "bytes" in chunk:
            parts.append(chunk["bytes"].decode("utf-8"))

    text = "".join(parts).strip()
    return json.loads(text)


def validate_result(result):
    missing = REQUIRED_FIELDS - set(result.keys())
    if missing:
        raise ValueError(f"Missing required fields: {sorted(missing)}")

    if result["severity"] not in {"low", "medium", "high"}:
        raise ValueError("Invalid severity value")

    if not isinstance(result["confidence"], int):
        raise ValueError("confidence must be an integer")


def lambda_handler(event, context):
    raw_text = event["raw_text"]
    alerts = sanitize_alerts(raw_text)

    result = invoke_agent(alerts)
    validate_result(result)

    return {
        "statusCode": 200,
        "alert_count_used": len(alerts),
        "triage": result,
    }
```

Expected result:

- Lambda can accept a raw Wazuh alert payload, call the agent, validate the result, and return triage output.

## Part 5: Guardrails and Troubleshooting

### Guardrails

Keep these protections in place:

1. Never send the full raw dataset if you only need a small evidence slice.
2. Never allow the agent to perform direct response actions in this lab.
3. Always validate the JSON response before storing or forwarding it.
4. Keep a human analyst in the approval loop.

### Troubleshooting

Common issues:

1. `AccessDeniedException`
   - Check the Lambda IAM role and Bedrock permissions.
2. Empty or malformed agent output
   - Tighten the Bedrock Agent instructions and verify the model returns JSON only.
3. Lambda timeout
   - Reduce the number of alerts passed to the agent.
4. Bedrock model access issue
    - Recheck that the chosen Bedrock model is enabled in your AWS account and region.
