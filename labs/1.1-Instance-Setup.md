
## Setting Up VM and SSH

In this lab, you will create an EC2 instance, connect to it from VS Code over SSH, and practice Linux terminal and file-permission fundamentals that are important in cybersecurity workflows.

1. Log in to AWS and open CloudShell. Then use the command below to create an SSH key.

```
aws ec2 create-key-pair \
  --key-name soc-lab-key \
  --query 'KeyMaterial' \
  --output text > soc-lab-key.pem
chmod 400 soc-lab-key.pem
```

2. From CloudShell, download the key before proceeding. Place it in your home folder.

3. Use CloudShell to create an EC2 instance. **Save the instance ID.**
```
aws ec2 create-security-group \
  --group-name soc-lab-sg \
  --description "SOC Lab SG"

aws ec2 authorize-security-group-ingress \
  --group-name soc-lab-sg \
  --protocol tcp \
  --port 22 \
  --cidr 0.0.0.0/0

aws ec2 run-instances \
  --image-id ami-xxxx \
  --instance-type t2.micro \
  --key-name soc-lab-key \
  --security-groups soc-lab-sg \
  --associate-public-ip-address \
  --query 'Instances[0].InstanceId' \
  --output text
```

4. Obtain and store the public IP address using the instance ID. Wait 10-20 seconds for the public IP to become available.
```
aws ec2 describe-instances \
  --instance-ids i-0abc123def456 \
  --query 'Reservations[0].Instances[0].PublicIpAddress' \
  --output text
```

5. Open VS Code and navigate to the Remote Explorer extension (computer icon). Hover over SSH and click the settings icon.

6. When prompted, select the top option: "C:\Users\username\.ssh\config".

7. Replace the file with the contents below, and be sure to update your username.
```
Host SOC-Instance
  HostName 18.144.31.55
  IdentityFile "C:\Users\username\soc-lab-key.pem"
  User ec2-user
```

8. Save the file. You should now see SOC-Instance under SSH on the left side. Hover over SOC-Instance and click the arrow to connect. In the lower-left corner of VS Code, the blue status indicator confirms you are connected.

9. Open a terminal with Terminal -> New Terminal. Run `hostnamectl` to view details about your VM.

10. Open your home folder in the file navigation pane.

## Terminal Basics

1. Run through these basic commands to familiarize yourself with the Linux terminal.

```
ls
ls -l
cd /
ls -l
cd ~
pwd
mkdir -p test
cd test
touch test.py
cd ..              # only run once, this is relative path not absolute
ls -l test/test.py # make use of the tab key to auto-fill
```


2. Step it up with permissions and execution of scripts!
```
echo 'echo Hello SOC' > hello.sh
chmod +x hello.sh
ls -l hello.sh
./hello.sh
```

### Quick Linux File Permission Chart

| Mode | Meaning | Typical Use |
| --- | --- | --- |
| 600 | Owner: read/write; Group/Others: none | Private keys, sensitive files |
| 644 | Owner: read/write; Group/Others: read | Regular text or config files |
| 700 | Owner: read/write/execute; Group/Others: none | Private scripts/directories |
| 755 | Owner: read/write/execute; Group/Others: read/execute | Executable scripts and public directories |

3. Practice permission changes with both absolute and relative modes.
```
chmod 644 hello.sh   # absolute
chmod 755 hello.sh   # absolute
chmod o-rwx hello.sh # relative
chmod g-x hello.sh   # relative
ls -l hello.sh
```

4. Advanced permissions: SetUID (the `s` permission) means that when the binary is executed, it runs as the file owner.
```
ls -l /usr/bin/passwd
# notice the s, the binary is owned by root.
# when you execute this, it runs as root.

ls -l $(which sudo)
```

Binaries with SetUID or SetGID can be a security risk. For example, if someone sets bash (or a renamed copy of bash) with `+s`, they may be able to execute bash as root and escalate privileges. Only binaries that require elevated privileges (such as `passwd` and `sudo`) should have this permission.

5. Finding files
```
find / -type f -perm -002 2>/dev/null


find / -perm -4000 2>/dev/null
# this is a useful command a security analyst may run to find privilege-escalation risks
```
