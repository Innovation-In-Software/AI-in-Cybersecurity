## Lab 2.1: CloudWatch AI Operations and Log Intelligence

This lab uses two AI-powered CloudWatch capabilities to analyze endpoint security logs: natural language query generation in Log Analytics, and AI Operations investigations. You will write no queries from scratch — CloudWatch AI writes and runs them for you.

No additional infrastructure or IAM changes required beyond your existing `soc-lab` setup.

## Attacker Objective (Cyber Lens)

Objective: Generate enough endpoint noise that AI-assisted analysis is required to distinguish signal from background activity.
ATT&CK focus: T1087 (Account Discovery), T1110 (Brute Force), T1059 (Command and Scripting Interpreter).
Defender outcome: Confirm that CloudWatch AI can identify the high-value events from your normalized alert stream without manual log grepping.

## Learning Objectives

By the end of this lab, you will be able to:

1. Use CloudWatch Log Analytics AI to generate Logs Insights queries from plain English.
2. Configure CloudWatch AI Operations with a retention policy and permissions role.
3. Run an AI-assisted investigation using natural language queries.
4. Evaluate AI-generated hypotheses as a SOC analyst.

## Prerequisites

- `/soc-lab/secure` log group with recent log events. Before starting, confirm live data is flowing:

  In the AWS Console, navigate to **CloudWatch** → **Logs** → **Log groups** → **/soc-lab/secure**. Open the most recent log stream and verify events exist within the last hour. If the stream is empty, SSH into your EC2 instance and run `sudo systemctl restart amazon-cloudwatch-agent` to resume log shipping.

- AWS Console access in `us-east-1`.

## Part 1: Query Logs with Natural Language

CloudWatch Log Analytics includes an AI-powered natural language interface that writes Logs Insights queries for you. This is a new capability — use it first before touching any other AI Operations feature.

1. In the AWS Console, navigate to **CloudWatch** → **Logs** → **Log Analytics**.

2. In the query input area, find the **Ask AI to write a query** search bar.

3. Enter the following prompt:

   ```
   Need to find failed SSH attempts
   ```

4. CloudWatch AI will generate a Logs Insights query. Review what it produces before running it — note which fields it filters on and what it is looking for.

5. Select `/soc-lab/secure` as the log group if not already selected, set a time range of **1 hour**, then click **Run query**.

6. Review the results. For each event returned:
   - Does the `@message` field contain an SSH authentication failure?
   - What field did the AI use to detect it — a keyword match, a structured field, or both?

7. Try a second prompt to compare:

   ```
   Show me escalation attempts
   ```

   Run that query against the same log group and time range.

   > CloudWatch Log Analytics AI generates standard Logs Insights syntax. You can copy any generated query, edit it manually, and save it to a dashboard — the AI output is not locked in.

## Part 2: Configure AI Operations

AI Operations must be enabled at the account level before investigations can be created. This step sets retention and provisions the permissions role.

1. In the CloudWatch left nav, click **AI Operations**.

2. Click **Configurations**.

3. If AI Operations has not been enabled, you will see an **Enable** or **Get started** prompt. Proceed through it.

4. Set **Investigation retention period** to **7 days**.

   > Investigations older than the retention period are automatically deleted. 7 days is sufficient for a lab environment and avoids unnecessary storage costs.

5. For the IAM role, select **Auto-create a new role with default investigation permissions**.

   > The auto-created role grants CloudWatch read access to your logs, metrics, and alarms within the account. It does not grant write access to any resources. You can inspect the role in IAM after creation — it will be named something like `CloudWatchAIOperationsRole`.

6. Click **Save** or **Enable**.

---

## Part 3: Run an AI Investigation

With AI Operations configured, create an investigation that uses AI to form hypotheses about your endpoint alert data.

1. In the CloudWatch left nav, click **AI Operations** → **Investigations** → **Create investigation**.

2. Select **From logs** as the investigation source.

3. If a helper query panel opens on the right side, close it by clicking the **X** in the top-right corner of that panel. This takes you to a query interface similar to Log Analytics.

4. Use the **Ask AI to write a query** bar to describe what you want to investigate. For example:

   ```
   Find failed SSH login attempts
   ```

5. Select `/soc-lab/secure` as the log group, set a time range of **1 hour**, and run the query to confirm it returns results.

6. Click **Create investigation** and give it a meaningful name, for example:

   ```
   failed ssh attempts
   ```

7. CloudWatch AI will analyze the results and generate hypotheses. For each hypothesis:
   - What conclusion did the AI reach? (e.g., likely misconfiguration, not an active threat)
   - What evidence did it cite to support that conclusion?
   - Do you agree with the assessment based on what you know about the activity that generated these logs?

   > A hypothesis of "likely misconfiguration from localhost" is a meaningful finding — it tells you the alert is low-priority and rules out active credential stuffing from an external source. Not every AI finding is an escalation; ruling things out is equally valuable.

8. Create a second investigation for a different threat angle:

   ```
   Find privilege escalation using sudo
   ```

   Compare the hypotheses CloudWatch generates for this vs. the SSH investigation.

9. Close each investigation when you are done reviewing it. In the **Investigations** tab, select the investigation, then click the **three-dot menu** (⋮) and choose **Close investigation**. Enter a reason when prompted — for example:

   - SSH investigation: `Confirmed localhost misconfiguration, not an active threat`
   - Sudo investigation: `Expected controlled lab activity, no escalation detected`

   > Closing investigations with a reason is good hygiene — it keeps the investigations list clean and creates an audit trail of analyst decisions.
