## Lab 1.3: AI-Assisted Security Scripting and IAM Review

This lab introduces AI-assisted engineering workflows for SOC analysts and cloud defenders. You will use an AI coding assistant to generate and improve security scripts, review IAM policies, and troubleshoot Python parsing issues while keeping a human reviewer in control.

Use any chat-based AI assistant: Amazon Q (via [q.aws](https://q.aws) with a free Builder ID), Claude (claude.ai), or ChatGPT. The prompts, review checklist, and workflow are identical regardless of which tool you use.

## Safety Rails

- Do not execute generated commands that modify production resources.
- Treat all AI output as draft code until you validate it.
- Do not paste secrets, tokens, private keys, or customer data into prompts.
- Keep all experiments in your lab account and lab VM.

## Attacker Objective (Cyber Lens)

Objective: Abuse weak automation practices to accelerate attacker reconnaissance and tooling.
ATT&CK focus: T1059 (Command and Scripting Interpreter), T1087 (Account Discovery).
Defender outcome: Enforce human review of AI-generated code and policy to prevent automation from introducing exploitable gaps.

## Learning Objectives

By the end of this lab, you will be able to:

1. Use an AI assistant to generate a log parsing utility from a clear prompt.
2. Apply a code review checklist to AI-generated Python before execution.
3. Use the IAM console to surface a real overpermissive policy warning, then use an AI assistant to generate the least-privilege fix.
4. Produce a repeatable AI-assisted workflow for secure scripting.

2. Use this prompt format for all AI interactions in this lab.

```text
Context:
- I am in an AWS cybersecurity training lab.

- [Describe exact function, inputs, and outputs]
```

## Part 2: Generate and Review a Parser Script

Ask your assistant to generate a parser (make sure you include some of the logs in the prompt):

```text
Generate a Python script named ai_generated_log_parser.py.
It must read sshd.jsonl and sudo.jsonl, then output:
1) failed SSH counts by source IP,
2) top sudo commands,
3) a CSV named ai_findings.csv with columns:
   event_type,source,description,count,severity_hint.
Use only standard library modules.
```

After generation, apply this review checklist before running:

1. Inputs and outputs are explicit and local files only.
2. No shell execution from Python (`os.system`, `subprocess` for external commands).
3. JSON parsing handles malformed lines safely.
4. Severity hints are explainable (not random labels).
5. No secrets, tokens, or account IDs hardcoded.

Run the script:

```bash
python3 ai_generated_log_parser.py
ls -lh ai_findings.csv
head -n 10 ai_findings.csv
```

If output is wrong or missing expected fields, refine prompt with exact defect details and regenerate.

## Part 3: IAM Policy Risk Review with Your Assistant

This part uses the AWS IAM console to surface a real security warning from an overpermissive policy, then uses your AI assistant to fix it. The output `least_privilege_lambda_policy.json` is the least-privilege Lambda execution role policy.

### Step 1: Create the bad policy and see the warning

1. In the AWS console, navigate to **IAM → Policies → Create policy**.
2. Click the **JSON** tab and paste:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "*",
      "Resource": "*"
    }
  ]
}
```

3. Click the **Visual** tab. The console will immediately show a security warning on the statement — this is AWS flagging that `Action: *` grants full access to every AWS service.

4. Take note of the warning text. **Do not save this policy yet.**

### Step 2: Use your assistant to generate the fix

The Lambda function needs exactly three permissions:
- Write CloudWatch logs
- Invoke a Bedrock Agent
- Read from and write to one S3 bucket prefix

Give your assistant this prompt:

```text
I have an IAM policy with Action: "*" and Resource: "*" for a Lambda execution role.
The AWS console flagged it as overpermissive.
Replace it with a least-privilege policy for these actions only:
- CloudWatch Logs write (CreateLogGroup, CreateLogStream, PutLogEvents)
- Bedrock Agent invoke (bedrock:InvokeAgent)
- S3 read from prefix arn:aws:s3:::soc-triage-input/*
- S3 write to prefix arn:aws:s3:::soc-triage-output/*
Return JSON policy only.
```

### Step 3: Apply the fix and confirm

1. Copy the AI-generated policy JSON back into the IAM console JSON tab.
2. Switch to the **Visual** tab — the security warning should be gone.
3. Name the policy `soc-lab-lambda-policy` and save it.
4. Save the JSON locally as `least_privilege_lambda_policy.json`.

> Keep the file in `~/soc-lab13/`.
